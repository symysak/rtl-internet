# rtl-internet

インターネット越しの `rtl_tcp` を、既存の SDR ソフトからそのまま滑らかに使うためのローカルプロキシ。

リモート側は **素の `rtl_tcp` のまま**で構いません。ローカルで本プロキシを動かし、SDR++ / GQRX / SDR# を `127.0.0.1:1234` に繋ぐだけです。ジッタ吸収・再接続・チューニング状態の復元はすべてプロキシ側で行うため、SDR ソフトからは LAN 内の `rtl_tcp` に見えます。

```
[SDR++/GQRX]  --rtl_tcp-->  [rtl-internet]  ==インターネット==>  [rtl_tcp + ドングル]
   127.0.0.1:1234              ジッタバッファ                      無改造
```

## なぜ必要か

`rtl_tcp` のプロトコルは LAN 前提の極めて素朴なもので、接続時に 12 バイトのドングル情報を送ったあとは生の 8bit IQ を垂れ流し、逆方向に 5 バイト固定長のコマンドを受けるだけです。フロー制御も欠落補償も認証もありません。そのままインターネットに出すと:

1. **ジッタがそのまま音切れになる。** SDR++ や GQRX はソケットを貪欲に読むため、単純に中継してもバッファは常に空のままで、RTT の揺らぎや再送が即座に途切れとして出ます。
2. **瞬断から復帰できない。** TCP が切れると SDR ソフトは「デバイス消失」として扱い、周波数・ゲイン等の設定も失われます。
3. **リモート側の欠落に気づけない。** クライアントが一瞬でも読み遅れると `rtl_tcp` 側のリングバッファ（既定 500 × 16384 バイト ≒ 8MB）が溢れ、サンプルが黙って落ちます。プロトコルに通知手段はありません。

## 設計の中核: わざと遅らせて出す

**「速く読む」ことではなく「意図的に保留して出す」ことが肝です。**

- 上流からは**常に全速で読み続ける**。読み止めると TCP バックプレッシャがかかり、リモートの `rtl_tcp` のリングが溢れて検知不能なサンプル欠落を招きます。溢れるならこちら側で溢れさせ、カウントします。
- 下流へは**サンプルレート由来のクロックでペーシングして書く**。これにより既定 500ms のクッションが維持され、ジッタと再送を吸収します。
- クッションの維持は**出力レートの比例制御**で行います。バッファが枯渇気味なら最大 10% 遅く出して滑らかに埋め直し（一時停止しません）、同じループがドングルの水晶とローカルクロックの長期ドリフトも吸収します。放置するとドリフトは遅延を無限に増やすか、バッファを枯らします。

欠落時は無音（`0x7f`）で埋めて下流を止めません。止まったソケットは SDR ソフトからは死んだデバイスに見えるためです。

## 使い方

```sh
go build ./cmd/rtl-internet

# リモートの rtl_tcp は localhost に bind し、SSH 経由で届かせる
ssh -N -L 15678:127.0.0.1:1234 pi@remote &
./rtl-internet --upstream 127.0.0.1:15678
```

あとは SDR ソフトの RTL-TCP ソースに `127.0.0.1:1234` を指定するだけです。

### セキュリティ

**素の `rtl_tcp` をインターネットに直接晒さないでください。** 無認証・平文であり、到達できる誰もが周波数・ゲイン・bias-tee を操作できます。本プロキシは暗号化・認証を行いません（意図的に非対応です）。SSH ポートフォワード、WireGuard、Tailscale 等でトンネルしてください。

本プロキシ自身も無認証なので、既定で `127.0.0.1` にのみ bind します。

### 主なオプション

| オプション | 既定値 | 説明 |
|---|---|---|
| `--upstream` | (必須) | リモート `rtl_tcp` のアドレス |
| `--listen` | `127.0.0.1:1234` | 下流 SDR ソフト向けの待ち受け |
| `--buffer` | `500ms` | ジッタバッファの目標深さ。そのまま追加遅延になる |
| `--buffer-max` | `2s` | 上限。超過分は最古から破棄し遅延の青天井を防ぐ |
| `--retune-prebuffer` | `150ms` | 周波数変更でバッファを捨てた後の再充填深さ |
| `--cmd-rate` | `20` | 同一コマンドの最大送出レート (回/秒) |
| `--takeover` | `false` | 新しい下流接続で既存セッションを置き換える |
| `--keep-upstream` | `false` | 下流が居なくても上流接続を維持する |
| `--stats-interval` | `10s` | 統計ログの間隔 |

回線が細い/揺れる場合は `--buffer 1.5s`、操作感を優先するなら `--buffer 200ms` あたりが目安です。

## 動作の読み方

10 秒ごとに 1 行出ます。

```
msg=stats depth_ms=482 target_ms=500 up_mbps=0.768 nominal_mbps=0.768 down_mbps=0.766
          conceal_ms=0 dropped_bytes=0 reconnects=1 connected=true
          stall_p95_ms=100 stall_max_ms=111
```

- `depth_ms` が `target_ms` 付近で安定していれば健全です。
- `conceal_ms` はバッファ枯渇で無音を挿入した時間。恒常的に出るなら `--buffer` を増やしてください。
- `dropped_bytes` はバッファ溢れ。下流が公称レートを消費できていない兆候です。

**`上流の到着レートが公称を下回り続けています` の警告が最重要です。** 素の `rtl_tcp` 相手では「リモートで落ちたサンプル」を知る手段が原理的に存在せず、到着レートと `sample_rate * 2` の比較だけが唯一の手がかりです。この警告は、回線帯域不足かリモート側リングバッファ溢れのいずれかを意味します。ジッタが区間境界に跨っただけの単発の落ち込みでは出ないよう、連続 2 区間の不足を要求しています。

## ドングル無しでの開発・検証

ローカルに `rtl_tcp` が無くても、同梱のモックで全経路を検証できます。悪条件も注入できます。

```sh
go build ./cmd/mock-rtl-tcp

# 150ms のジッタを乗せ、30 秒後に切断する
./mock-rtl-tcp --listen 127.0.0.1:18000 --sample-rate 48000 --jitter 150ms --drop-after 30s

./rtl-internet --upstream 127.0.0.1:18000 --assume-sample-rate 48000 --stats-interval 2s
```

`--rate-factor 0.9` で帯域不足を、`--rate-factor 1.001` で水晶ドリフトを模擬できます。モックは既知のカウンタ列を流すため、欠落位置を正確に特定できます。

```sh
go test ./...           # ユニット + 結合テスト
go test -race ./...
```

## 制限

- **帯域は削減しません。** 2.4Msps なら約 38Mbps が常時流れます。デシメーションや圧縮にはリモート側の相方が必要で、素の `rtl_tcp` 相手では原理的に不可能です。フルレートを運べる回線が前提です。
- 下流クライアントは同時 1 つです（`rtl_tcp` 自体と同じ）。
- 暗号化・認証は行いません。上記のとおり外部トンネルを使ってください。
- 周波数変更の直後、往復遅延ぶんだけ変更前の信号が残ります。バッファは捨てますが、飛行中のデータまでは捨てられません。
- librtlsdr fork の `REPORT_I2C_REGS` (0x48) は有効にしないでください。IQ 以外のデータがストリームに混入し、時間換算の精度が落ちます。バイト列としては素通しするため致命的ではありません。

## 構成

```
cmd/rtl-internet/     CLI
cmd/mock-rtl-tcp/     ドングル不要の検証用フェイクサーバ
internal/rtltcp/      プロトコル (12B ヘッダ / 5B コマンド / opcode)
internal/ring/        ジッタバッファ (最古破棄、サンプル境界を維持)
internal/pacer/       ペーシングとドリフト制御 — 中核
internal/state/       コマンド状態と依存順リプレイ
internal/upstream/    再接続する上流クライアント
internal/server/      ローカル待ち受けとコマンド合流
internal/stats/       カウンタと診断ログ
internal/mockrtl/     モック実装
```
